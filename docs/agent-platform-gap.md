# Agent 平台化补强边界

第二篇经验帖提到的能力里，TravelMind 已有 LangGraph 状态编排、短期/长期记忆、RAG、评测、超时/降级和工具权限。此次补了两个最小平台化能力：

## 经验帖能力审计

| 能力 | 当前最小闭环 | 证据边界 |
|---|---|---|
| 架构范式 | LangGraph 固定主链路、条件回环、并行分支和 checkpoint 局部重规划 | 单机工作流，不是分布式 Agent 平台 |
| 上下文与记忆 | 状态内轮次记忆、SQLite 结构化画像、按 user_id 隔离的 Chroma 语义记忆 | 当前请求始终高于历史偏好；没有无限会话记忆 |
| RAG | 30 条检索集（24 正例 + 6 no-answer）、关键词/Chroma 独立召回、RRF、来源标签、弱向量最近邻拒答和注入隔离 | 仍只有三篇项目文档；尚未评估生成答案忠实度，不能代表线上答案质量 |
| 评测与轨迹 | 单元/契约测试、消融、30/30 高德 POI fixture、run trace、脱敏工具轨迹、4 类失败/重试合约、Token/延迟指标、3 案例真实三模式消融和 2 案例真实故障恢复 | 当前真实消融每例只跑 1 次；完整集合与重复稳定性尚未运行 |
| 模型理解与路由 | 统一工厂内按任务类型选择主/小模型，默认关闭 | 无真实多模型 A/B，不能声称成本下降 |
| MCP/A2A | Agent Card、Tool Manifest、Task Envelope 本地契约 | 非远程 MCP Server 或 A2A 网络实现 |
| 稳定性/安全/成本 | 超时、有限重试、依赖降级、工具权限、工具参数脱敏、RAG 注入防护、用户隔离、预算门禁 | 单进程内存 trace；未做多实例生产部署 |

## 风险触发式多 Agent

真实消融没有证明自然请求固定执行 Reviewer/Time Check 有质量收益，却证明独立审核能修复已知异常草案。因此主流程改为确定性风险门控：低风险草案跳过两个模型审核节点，高风险草案按风险类型升级，并在最终结果的 `audit_policy` 中返回风险标签和跳过决策。保存真实输出回放的 3 个自然样本全部跳过、2 个注入故障全部升级；61.8% Token 和 50.7% 延迟节省来自回放投影，尚未经过更大规模在线 A/B。

以上七项已具备与项目规模相称的实现或明确边界。后续不再为简历堆同类框架；优先补真实评测数据和能解释的对照实验。

## 模型路由

`app/llm/router.py` 提供确定性的 `ModelRouter`，并已通过统一 LLM 工厂接入主流程：Intent、Query Rewrite、画像/语义记忆抽取以及输入较短的餐饮和贴士任务可路由到同一供应商的小模型，Planner、Reviewer 和 Judge 保留主模型。`LLM_ROUTING_ENABLED` 默认关闭，因此不会改变现有线上行为；开启时还必须配置当前供应商真实可用的 `LLM_SMALL_MODEL`。

当前只完成了可运行的静态路由闭环和离线契约测试，没有真实多模型 A/B 数据，也没有实现跨供应商故障切换。面试中只能说明“主流程已支持按任务类型路由”，不能声称已经验证成本下降或质量不损失。

## MCP/A2A 形状的协议边界

`app/multi_agent_core/protocols.py` 提供：

- `MCPToolManifest`：工具名、描述、输入 schema 和允许的 Agent；
- `AgentCard`：Agent 能力与可接收任务类型；
- `A2ATaskEnvelope`：发送方、接收方、任务类型、trace、attempt、状态和结构化 payload。

`ToolRegistry.manifest(agent)` 和 `Supervisor.agent_cards()` 可用于本地发现与审计。当前没有实现远程 MCP Server、A2A 网络传输、服务注册中心或分布式一致性；面试中应称为“协议化本地契约原型”，不要说成已经接入官方协议生态。

POI Agent 的实际工具调用已统一经过 `ToolRegistry.call`，不再只在 Agent 内做字符串权限判断。每次调用记录 Agent、工具、成功/失败/拦截状态、错误类型和耗时；城市可用于参数校验，自由文本查询只保存长度与短哈希。`python -m tests.eval.run_trajectory_eval` 用 4 个离线场景验证正常链路、Reviewer 打回、瞬时超时重试和持续失败，当前均通过 8 项轨迹合约。这证明的是路由与失败处理，不证明 LLM 规划质量。

## 选型边界

固定的旅行规划主链路仍使用 LangGraph，因为节点依赖和合流关系稳定；只有当工具/Agent 需要跨进程发现、异构团队接入或独立扩缩容时，才值得把这些本地契约升级成真正的 MCP/A2A 服务。
