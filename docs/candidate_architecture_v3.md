# 候选池生产链路升级 v3

## 实现与边界

- 高德 POI 解析：类型白名单决定建筑内场馆属性，名称出现遗址公园、森林公园、广场、露天、户外、外景时不认证室内。来源 `amap_type_verified` 只表示分类规则验证，不是实地核验或全程避雨保证；仅凭名称像博物馆仍为未知。官方证据属性开启时可进一步覆盖分类推断。
- 默认过滤家居建材、公司企业、汽车服务/销售、医疗保健、生活服务中的中介/维修。对明显误分类的系统门窗商户增加名称拦截，避免原快照中绿盾商户凭博物馆分类入池。非文旅例外必须同时具备用户精确引号点名和服务端 `candidate_force_named_non_tourism` 开关，普通 Prompt 不能开启。
- Validator 先清理旧池和重复名称，再输出 `missing_named_pois`、`indoor_shortage`、`count_shortage` 及额外多样性缺口；历史 checkpoint 的类型标签也按新规则更新。排除项支持明确引号名称；一般自然语言复杂排除仍需模型理解与后续审核，不声称完全规则化。
- 当前原始请求及本轮修改保留，显式约束、老人/幼童或天气风险出现时抑制历史偏好。雨雪/恶劣天气或日间温度至少 35℃要求两个室内储备；只去室内则要求整个候选目标数满足。室内储备是备选数量，不自动强制最终路线全部室内。
- 模型输入只含城市、剩余预算、融合偏好、名称/室内简表、Active Gaps 和查询黑名单。黑名单同时给出哈希和查询/分类，模型不需要反推哈希；工具执行前再次去重。缺失点名优先，其次室内缺口，再补数量/类型。`EXACT_NAME`、`INDOOR_CATEGORY`、`THEME`、`STOP` 为新动作，旧动作保留兼容；代码校验不依赖模型服从 Prompt。
- 上限维持两轮，默认共享四次 HTTP（含重试）；耗尽前停止请求模型。LLM 决策失败退化为经过同一缺口策略校验的服务端动作。State、checkpoint 持久化和可选 Supervisor 的输入输出权限同步更新。

本次不逐景点调用 AI 打标签，**标签模型 Token 为 0**；ReAct 仍需决策模型，未运行真实模型对照，因此不能给出 ReAct Token 降幅或新的最终路线成功率。

## 离线结果

固定 28 个受控场景，23 个缺口、5 个边界。两组共享相同初始池；基线不补查，实验组运行实际生产图的决策包装、搜索、校验、路由。模型由读取当前缺口的策略替身代替，高德响应固定回放，无外部付费调用。

| 场景 | 基础池 | 有界补查 |
|---|---:|---:|
| 点名 | 0/9（0%） | 9/9（100%） |
| 室内 | 0/9（0%） | 7/9（77.78%） |
| 数量 | 0/5（0%） | 4/5（80%） |
| 非边界合计 | 0/23（0%） | 20/23（86.96%） |

基线为零源于专门挑选已有缺口的状态，不能当成生产基础检索总体水平。通过要求全部点名命中、去重数量和室内数量同时满足，评分不调用生产 coverage 函数。仍失败的三条为三亚固定响应经过评分过滤后容量不足：`indoor-3-1`、`indoor-3-2`、`count-3`。未降低评分阈值、伪造响应或删除失败。

边界安全退出 5/5，预算/轮次合规 28/28，重复查询拦截 6/6，虚构/近名错误接纳 0/2；平均 1.3214 轮、1.5357 次补查 HTTP。报告属于候选前提机制评测，不是最终规划任务成功率。

v2 原始资产及报告保留；v3 仅将 `named-3-3` 的误分类商户换成同一已采集三亚快照中的三亚自然博物馆，并保留原字段与来源。其他失败容量未扩充。v2 与 v3 不能视作完全不变测试集上的算法提升。
