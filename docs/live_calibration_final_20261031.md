# 总时间窗口与高德官方名称：最终补丁验收

## 实现口径

- Intent/State 增加 `max_duration_hours`、`latest_end_time`。确定性解析覆盖“4小时内”“只有四小时”“半天”“下午3点前结束”等明确表达；未命中时使用结构化意图结果，不凭空补时限。
- `quality.time_slot_violations` 对每天所有景点和餐饮区间取最早开始与最晚结束，空档和交通时间不从跨度中扣除。超过最大时长或最晚结束时间时产生 L1 `time_window_exceeded`，不会提升为 L0。
- Planner 接收明确时限与上一版确定性问题，时间窗返工反馈优先要求删除非必要餐饮、压缩停留；景点30分钟、餐饮20分钟的下限仍生效。硬问题存在时不能早停，耗尽返工后仍可通过 Tier 2 返回带提醒的 `PARTIAL_SUCCESS`。
- 名称匹配支持归一化、限定后缀和完整核心字符的有序子序列（插入跨度受限，核心须位于候选名称末端，或先去除限定场馆后缀）。停车场、公厕、交通设施、酒店及餐饮等附属 POI 先过滤；不会把“解放碑剧院”“解放碑步行街”直接视为纪念碑。
- 点名查询把原始称呼存入匹配 POI 的 `aliases`；规范全称优先于任何别名/模糊匹配，避免池内排序改变官方名称身份。候选覆盖、Planner 名称归一化、`unknown_poi` 与 `missing_must_visit` 使用一致的映射入口。
- 候选动态 HTTP 预算写回 checkpoint。单个查询变体耗尽重试额度属于 `SEARCH_FAILED`，只有真正触及共享预算前置检查才记为 `BUDGET_EXHAUSTED`。外部错误不作为“现实地点不存在”的证据。

## 真实联调口径

使用生产 LangGraph、真实 `openai-proxy / gpt-6.1-sol` 与高德 API。每单最多返工3次/4份快照，补查最多2轮，共享候选预算 `min(10,max(4,点名数量+2))`。请求文本不变，脚本禁用 Redis，仅显式追加复跑，不隐藏失败记录。

候选 HTTP 次数不含天气、餐馆及道路请求。以下均为单次运行观测，不能视为平均/P50性能。成本记为 `unpriced`；没有供应商精确usage时不声称实测Token节省。
