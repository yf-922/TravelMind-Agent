# 景点属性：先补事实，再验证路线是否改善

## 当前实现

南京、上海、三亚共 12 条具名景点属性，保存在 `knowledge/poi_attributes_v1/catalog.json`。属性包括参观环境、展陈主题、官方明确描述的步道或游览注意事项；不推测无障碍等级、老人安全等级、实时票价、预约余量和开放时间。每条事实保留 HTTPS 来源、采集日期、原文引用和快照哈希。

这些标签是作者依据官方材料提取、核对引用的草稿（`author_extracted_quote_checked`），未经用户逐条人工确认。历史介绍中的建设规划不当作当前已开放事实。`indoor_main` 仅指记录限定的馆内展厅，不包括庭院、排队与通勤；`mixed` 和 `unknown` 都不能满足“只去室内”的硬限制。

上线读取本地资料，不为每次规划额外调用 AI 或地图。匹配需同城市、精确景点名，且已知双方 POI ID 一致；缺少 ID 时还需坐标距离在 200 米内。同名异地或异馆区不模糊套用。证据超期、来源损坏、身份不匹配或开关关闭时清除本模块旧覆盖，避免 checkpoint 带回旧的室内认证。期限默认 180 天，不能替代出行前事实核验。

## 接入位置

1. Candidate ReAct 判断缺口前刷新原候选属性；补查后再刷新新增候选。
2. 联合 Planner 对恢复的 checkpoint 重新刷新，属性连同来源进入候选描述。
3. Planner 返回同一份 POI 状态，供规则、Reviewer 与后续检查使用。
4. 最终结果的 `poi_attributes` 仅列出所选景点的属性与证据。

候选集合、顺序、坐标、实时票价与开放时间不被属性模块修改。开关 `POI_ATTRIBUTES_ENABLED=1` 显式启用，默认 `0`；实验不会改写用户 `.env.local`。

## 真实模型对照协议

固定在模型调用前保存的 10 条作者草稿请求，每城使用原有 6 个真实候选。覆盖室内避雨、科举、生命演化、湖泊园林、老人避不平步道、海岛渔村和海滨奇石；另含必须去豫园却要求纯室内，以及三亚候选缺乏纯室内证据两个明确拒绝对照。原计划每组每请求重复两次，共 40 次路线试验；用户后续要求先小规模看效果，因此收敛到首轮 20 次路线试验。第二轮已开始的调用单独留档，不混入首轮质量比较。

有属性、无属性使用相同候选、天气、模型、Prompt 模板、道路响应回放、审核流程和返工上限。两组共同将旧类别猜测归为 `indoor_hint`，不当作已核实室内；因此该实验比较的是当前生产适配器语义下有无事实属性，并非旧的启发式布尔标签方案。

真实模型运行生产联合 Planner → 道路核验 → Risk Gate → Reviewer/返工 → 时间核查 → 最终输出。上游天气/候选固定，RAG 关闭；贴士分支固定为空，餐馆未提供候选，不能据此评价餐饮或完整在线端到端服务。道路不调用外部服务。

评分只读最终路线。正例需通过最终审核、非空、不重复、无池外点、满足限定景点数、游览时长、预设兴趣与排除偏好，以及同一参考属性下的室内限制。负例需明确拒绝原因，不能把异常或空响应算拒绝成功。两组评分均使用相同参考属性；部分硬约束复用生产代码，属于探索性诊断，不是独立人工认证。重复试验不增加独立请求数量。

最多 240 次模型调用，每次最多 4096 输出 Token，关闭 SDK 自动重试；失败保留原始状态，不用成功重跑覆盖。仅累加响应实报输入/输出 Token，缺失不补零；价格未确认记为 `unpriced`。连续两次模型调用失败或总调用预算耗尽即停止。

本次小试发现复制 LangChain 配置不会自动重建底层 SDK：前 26 次调用的内部 HTTP 重试次数不可统计，不能称作严格的 26 次 HTTP 尝试。暂停后通过 SDK `with_options(max_retries=0, timeout=60)` 修正实际客户端；暂停中的上海无属性试验记为 `HarnessInterrupted`，保留两次调用尝试，不重新运行覆盖。此前已完成的 6 次最终路线试验直接复用。后续账本另记协议修订，不把这次中断当作模型质量失败的证据。

按用户要求，后续改为最多 2 个独立进程并发，SQLite 原子预留共享调用预算，各进程独占环境变量、地图替换与输出账本。同一路线仍按规划→审核→返工依赖执行，不能并发打乱。切换时未完成的三亚无属性试验同样记中断。总体结果保留中断分母；属性改善/退化只在两组均完成且无执行错误的配对中比较。串行与并发阶段的耗时不混用来宣称加速。

```bash
# 资产、来源和回放预检查，无付费请求
python scripts/evaluate_poi_attributes.py

# 真实模型实验：要求新输出目录，避免覆盖已完成账本
python scripts/evaluate_poi_attributes.py --run --workers 4 --repetitions 1 --max-calls 240 --out data/poi_attributes_v1/new_run

# 只从已有账本重建报告，不初始化模型，不产生 API 调用
python scripts/evaluate_poi_attributes.py --summarize-only --repetitions 1 --out data/poi_attributes_v1/pilot_20261030

python -m pytest -q tests/test_poi_attributes.py tests/test_frozen_protocol_guard.py
```

运行账本、完整 Prompt、逐请求最终状态保存在忽略的 `data/`。汇总结果发布后在本页链接；正式启用前需复核属性、收益与退化案例，不以新增来源数量或解释更长代替选点收益。

并发支持 1/2/4/8 个独立进程，默认 4；原子调用总预算不随并发数扩大。创建输出目录内的 `STOP` 文件可在当前试验结算后停止追加任务，恢复后需先移除它。本次已执行部分仍使用 1/2 路，不能称作已经测试过 4/8 路在线吞吐。

## 本次小试结论（2026-10-30）

首轮 10 条请求共 20 个组别状态明确：18 个最终结果与 2 个切换工具造成的中断。不能把中断导致的差额算属性收益。

| 口径 | 无属性 | 有属性 |
|---|---:|---:|
| 首轮正常请求（含 1 个无属性组中断） | 6/8（75%） | 8/8（100%） |
| 首轮两类拒绝对照（含 1 个无属性组中断） | 1/2（50%） | 2/2（100%） |
| **两组均完成的 8 个配对，含 1 个拒绝对照** | **7/8（87.5%）** | **8/8（100%）** |
| 其中两组均完成的 7 个正常请求 | 6/7（85.71%） | 7/7（100%） |

可比较配对中改善 1/8、退化 0/8，其余 7/8 两组均正确。南京雨天请求无属性时没有可认证室内候选，返工后仍返回拒绝；有属性时选中南京博物院，安排馆内展厅 120 分钟，并通过最终检查。科举、生命演化、湖泊、渔村与奇石兴趣请求两组选点一致。老人请求从海洋水族馆改为自然博物馆，两者均可接受，不能计作收益。豫园纯室内矛盾两组均拒绝。

本轮正常请求均为单景点的一日行程，主要隔离属性可核验性与兴趣选点，**没有验证多景点动线、通勤安排或三日容量改善**。结果支持为已证实的参观范围提供属性，不支持大批量 AI 猜标签或扩大知识库；生产默认开关暂保持关闭。

首轮加上停止前已开始的第二轮工作，共留下 98 次模型调用记录，94 次有返回且有实报用量，4 次中断用量未知；已知输入 718,163 Token、输出 25,213 Token。未知部分不补零，费用 `unpriced`；前 26 次底层 HTTP 重试次数未知。这些是全部工作用量，不是首轮可比较配对的成本，更不能据此宣称降费。

逐请求表见 [属性小试报告](poi_attributes_pilot.md)，机器可读汇总见 [JSON](poi_attributes_pilot.json)。待审标签及单次小样本结果不写成正式线上成功率。

最终验证：`python -m pytest -q` 为 **740 passed，3 条依赖弃用警告，30.59 秒**；`python scripts/validate_eval_assets.py` 通过。当前专项覆盖身份与馆区匹配、证据哈希/引用、过期清理、混合环境、共享状态传递、SDK 重试关闭、并发预算原子预留、缺失 Token 与中断不充当质量收益。4/8 路 API 吞吐未实测。

## 冻结报告与代码变更

旧的 50 条冻结实验仍要求源代码指纹一致。本次修改 Planner 后，旧实验不能直接重跑并沿用旧报告名称；必须在旧代码版本复现，或另建新实验版本。资产完整性单测与正式评测的协议指纹校验分开，正式入口默认仍严格拒绝源代码漂移，另有回归测试保证此限制有效。
