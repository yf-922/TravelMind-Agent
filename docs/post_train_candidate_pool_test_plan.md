# 真实检索候选池对照诊断

目的：检查当前开发集的3–4个候选是否放大重复景点等错误，以及增加真实候选后是否改善。不能预设扩池必然改善，也不能据此推翻稀疏场景的有效性。

## 已完成采集

南京、上海、三亚各20个候选。保留已有6个候选及其原始属性，追加高德真实检索结果；全部30个输入最终均为20个候选。原始搜索响应、检索动作、过滤理由保存在 `data/post_train/candidate_pool_live_v1/`，不写回旧母本或训练数据。

采用生产可用的风景名胜、博物馆、公园搜索，offset=25；保留评分缺失候选，已知评分低于4.5则按生产规则过滤。坐标无效、异市、设施点、同名/明显父子点及150米内重合点过滤，人工检查剔除中山陵祭堂、玄武湖情侣园、西岛牛王岭等。父子关系检查不是完整实体认证。

新点的室内属性保留未知；不得根据名称把博物馆标成全范围室内。旧标签仍是历史快照声明。开放时间保留高德原文，复杂节假日/日期解析及事实时效性仍有限制。

## 实验设计

- 开发集30个相同需求，包含1–3天、天气、每日数量和必去限制；不访问丽江/景德镇独立测试。
- v2、v3分别生成3个随机种子（42/43/44），温度0.3、输出上限2048，新增180次本地推理；原始3–4候选的180条请求结果已保存，复用为配对对照。
- 除候选列表外，保留原状态所有其他字段。实际输入通过生产Joint Planner边界捕获，不手工重写提示词。
- 20候选输入经服务器原始tokenizer检查为3039–4136 tokens（未计输出）；最大合计6184，所以本实验服务上下文设8192，结束恢复Base默认4096。输出限制不变，不截断候选或提示词。
- 推理完成后只为实际选择的有向路段补高德道路响应，按坐标、模式缓存。最多400个新路段调用；缺失仍记road_unverified。推理与道路评分分离，禁止根据答案修改评分规则。
- 旧道路记录保留，新增道路存独立资产；同一新路段各模型共用同一回放。原始输出、初评和补齐道路后的复评分开保留。

## 判断指标

1. 重复景点案例率与逐题修复/退步名单：判断扩池是否缓解跨天重复。
2. 硬约束通过、规则与解释共同通过：检查是否把重复换成交通、开放时间、候选越界或解释错误。
3. 平均景点数、非空天比例：检查是否靠少排和空日取得表面通过。
4. 道路证据缺失、室内未知及天气错误：区分数量够与可用候选够。不能把未知当已认证室内。
5. Token及延迟：评估扩大上下文的实际成本。

解释限制：扩池同时增加数量、类别选择和未知属性，不是纯数量的单变量实验；检索以博物馆等类别扩充，也不是全体生产流量分布。90次重复生成只对应30个独立需求。后续如要分离数量和类型影响，需要在同一冻结大池中分层抽取不同规模子集，并报告约束可行性。
