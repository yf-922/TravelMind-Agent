## 训练数据与正确答案

新增96条：48条数量不可行、48条相邻有解样本，形成48对。使用历史v2训练输入中的真实离线候选快照，候选名称、开放原文及坐标不改写；天气、日期、需求数量是明确的合成控制变量。候选1/2/3个各32条，天数分别1/2/3，每次参观60/75/90分钟。5个训练城市：三亚20、上海20、南京20、成都18、苏州18条。

同一对两个输入的所有结构化字段相同，消息只改变“恰好需要几个不同景点”；候选覆盖状态都固定pending，不把“insufficient/ready”标签泄漏给模型作为答案线索。提示仍直接捕获当前生产`capture_messages(state)`，不加入额外system或few-shot。当前生产协议和现有已用训练文件不修改。

例如，同一个2天、仅2个候选的输入：

| 条件 | 正确输出 |
| --- | --- |
| 恰好3个不同景点，禁止新增/重复 | 保留2天，各天spots=[]；说明候选2、需求3、缺1，建议补候选或降低数量；不把部分路线声称为满足 |
| 恰好2个不同景点，禁止新增/重复，每天至少1个 | 每天1个、全程不重复，给出符合开放窗口且足够时长的时间表 |

这些目标是确定性证明和可行时间表构造，不是教师模型生成，也不是mock输出；新增付费API调用为0。不存在城市交通安排时的道路猜测：有解目标每一天只有1个景点，没有相邻景点路段。

本实验只修数量不可行；不混入高温unknown室内不可行。该类错误仍需后续独立覆盖，不能提前宣称已解决。

## A/B训练设计

| 项目 | A：v2继续训练 | B：混合数据从基座重训 |
| --- | --- | --- |
| 起点 | 已合并v2-current，原v2已训练48步 | 原始Qwen2.5-7B-Instruct |
| 新增训练集 | 96条配对新数据 | 原v2的250条＋同一96条，共346条 |
| 本轮优化步数 | 48 | 96 |
| 完整路径累计优化步数 | 48＋48＝96 | 96 |
| 每设备batch / 梯度累积 | 1 / 16 | 1 / 16 |
| LoRA | 新rank16，alpha32，all | 新rank16，alpha32，all |
| 学习率 | 1e-4 | 1e-4 |
| 精度/注意力 | BF16 / SDPA / gradient checkpointing | 相同 |
| 截断长度 | 3584 | 3584 |
| seed | 42 | 42 |
| 验证/保存 | 每16步，分别报告数量与原验证loss | 相同 |
| 主对照权重 | A最终step48（路径累计96） | B最终step96 |

不按各自最佳验证loss选择不同步数，避免“相同步数”要求变成不同训练预算。A是以v2已合并权重为基础新建LoRA，并非恢复旧优化器动量；明确采用相同的新优化器和调度器。先分别做最长16条、5步冒烟，两组均通过才开始全量；A/B按GPU0顺序运行，任何子阶段失败即停。

重要边界：修订后完整路径累计步数均为96，每步有效batch配置均为1×16；但样本Token长度和跨epoch尾部batch会导致实际样本数与Token不同。A前48步学习旧v2数据、后48步学习新增数据；B96步学习混合数据。A新增96条约曝光8遍，B346条约4.4遍，A阶段无解目标占50%，B约13.9%。累计步数相等，学习率是两阶段各自48步调度或单阶段96步调度，课程顺序、混合比例、任务曝光仍不同；不能称为其他所有因素都相同的纯起点消融。本次不擅自增加第三组。

## 训练后要检验什么

与冻结v2-current比较，不仅比较A/B：

1. **数量无解正确处理率**：20条跨城市无解题×3seeds，判定空路线与解释数量正确；另单列原50题的3道数量无解题，作为历史开发参照。
2. **有解误拒绝率**：20条配对有解题×3seeds，不允许模型看到稀疏候选就拒绝；同时检查候选内、去重、完整天数、开放时间。
3. **旧能力保留**：原50题×3seeds，Planner-Only和Rules+Rework；重点比较常规有解和解释一致性。高温无解单独列出，不能与数量无解混为一种收益。
4. **配对成功率**：同一候选下有解、无解两条都正确的比例，避免靠“全拒绝”获得无解高分。
5. **稳定性与成本**：同题3seed稳定通过数、平均返工、生成Token、耗时；按case-family bootstrap处理相关重复。

验证loss用于观测训练和遗忘，不替代上述生成式指标。先完成训练与产物核查，再运行评测；本次未自动启动新的评测调用。
