## 具体错误与版本判断

不同故障可出现在同一结果上，且`opening_evidence`和`opening_time_conflict`常同时标记，不能把故障数直接相加当失败样本数。

| 模型 | 直出关键错误 | 返工后关键剩余错误 |
| --- | --- | --- |
| Base | 用户时间窗14；开放冲突13；高温/未知室内5；无解仍排8 | 时间窗13；开放冲突10；无解仍排7 |
| v1-current | 无解仍排15；时间窗12；游玩不足8；解释时长标记8 | 无解仍排15；开放冲突5；时间窗5；解释时长标记8 |
| v2-current | 无解仍排15；开放冲突11；高温/未知室内6；休息窗5 | 无解仍排15；开放冲突12；高温/未知室内2；通勤1 |
| v2-large | 无解仍排15；时间窗12；开放冲突10；天数8；解释时长标记12 | 无解仍排15；开放冲突8；天数7；时间窗6；解释时长标记14 |

1. **v2-current**：直出时间窗错误由Base的14降到1；必去遗漏由6降到1。直出高温6次并未优于Base的5次；返工后降到2。优先保留作后续基线，不立即部署。
2. **v1-current**：有解规则能力有提升，尤其返工后；但解释时长一致性弱于v2，且无解处理退步。其纯规则121对120的1条优势不值得单独放大。
3. **v2-large**：天数结构和解释时长错误更明显，直出共同通过低于Base4个百分点。扩大候选池不保证收益；本版本与v2同时存在样本量、候选分布、历史训练等差异，尚不能把失败归因为候选池增加。
4. **Base**：常规路线弱于current SFT，但部分无解处理保留得更好，是必要的退化检测参照。

## 无解样本揭示的语义盲点

实际核对v2-current的seed42输出：

- 南京输入只有两个候选、要求恰好三个不同景点，输出两个景点，却在notes写“按2个候选安排恰好3个不同景点”。
- 三亚和苏州也出现“仅安排2个……满足恰好3个”的矛盾。
- 上海、成都输入室内属性未知且高温限定室内时段，仍安排景点，并把它描述成明确室内。

这是输出本身的语义错误，而非仅仅没有命中评分关键词。不过现有解释检查未完全识别这些数量与证据矛盾；无解rubric已经将这些结果判失败。因此“共同通过”不代表解释语义全覆盖。首要工作是核对训练集中是否存在同类冲突、是否缺少明确不可行的训练目标；尚未完成该审计，不能断言根因已确定。

返工反馈目前只提供规则错误代码，且不包含完整上轮输出。对“不可行”“开放窗口”等复杂问题，这可能限制修复效果，但本轮没有对反馈形式做独立消融，不能直接认定为原因。v2返工开放冲突11→12、某城市分数下降，来自两种模式分别生成的结果及重排可能引入新错，不能把聚合差异当成逐样本同一答案必然恶化；逐轮ledger可用于后续定位。

## 证据强度和后续次序

v2相对Base的共同通过差异：直出+6.67pp，案例分层bootstrap 95%区间[-4.67,18.67]；返工+4.00pp，区间[-5.33,13.33]。v2相对v1：直出+6.67pp，区间[-4.67,18.67]；返工+2.00pp，区间[-4.67,8.67]。区间均含0，只能说本轮表现更好，尚不足以证明总体显著优于。

建议按以下次序推进，不再无方向增加训练数据或马上DPO：

1. 冻结本轮v2-current与结果，审计训练中的候选数量不可行、室内unknown被升级、开放窗口冲突和解释矛盾，分清缺覆盖与错误目标。
2. 固定当前评分结果不改，另版本补强数量与属性证据的语义审计；用人工复核确认失败，不能为了提分放松评分。
3. 如需补数，优先合成新的同类约束组合和明确不可行答案，不使用这50题的原题或标准答案；保持正常有解案例，防止模型过度拒绝。
4. 在新的未参与调参的独立测试上验证v2与Base，分别报告有解成功率、无解正确处理率和错误拒绝率。已有50题多次用于诊断，属于开发基准。
5. 当前阶段先修事实/可行性和语义正确性；DPO更适合在此基础上进一步比较合法路线的偏好质量。现有版本并未展示DPO收益，不应提前承诺。
