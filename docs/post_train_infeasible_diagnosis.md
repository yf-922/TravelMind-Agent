# 无解能力退步核查：数据准入、生产规则与评测协议

本次仅进行离线诊断，不修改生产逻辑、训练数据或冻结评测，不调用API、不重新训练。复现命令：`python -X utf8 scripts/audit_infeasible_sft_diagnosis.py`。完整输入与输出证据：`data/post_train/infeasible_diagnosis_20261025/evidence.json`。

## 结论

已证实数据准入、验证覆盖和线上风险规则对“有证据的不可行结果”缺少独立分支；这是本次训练流程中的设计缺口，不能归咎于用户要求。正确无解答案在评测中合法，但在本次合成审核中被无条件拒绝，三个SFT数据集与验证集均没有对应输出样本。SFT后模型在这5道题上持续硬排路线，有时还编造满足说明。

这些证据支持“训练分布偏向始终排出路线，未保留不可行处理能力”的机制解释。但尚未做受控补数/规则修复消融，不能把各机制的因果贡献或7B容量影响量化。已确认的流程缺陷足以优先修复，不需要先增加训练时长或直接进入DPO。

## 1. 测试题本身是否真的不可行

逐题读取实际传给模型的messages及state，而非只看case标签：

| 题目城市 | 独立可核验冲突 | 证据 | 正确空行程是否符合Schema/评分 |
| --- | --- | --- | --- |
| 南京 | 恰好3个不同景点，但仅2个候选，禁止新增/重复 | 实际唯一候选数=2；用户明确禁止部分路线冒充满足 | 是 |
| 三亚 | 同上 | 实际唯一候选数=2 | 是 |
| 苏州 | 同上 | 实际唯一候选数=2 | 是 |
| 上海 | 38°C，只能11:00–15:00，至少1个明确室内景点 | 实际23个候选，indoor全部unknown，明确室内=0 | 是 |
| 成都 | 同上 | 实际22个候选，indoor全部unknown，明确室内=0 | 是 |

所有题目明确要求无解时保留天数、当天`spots=[]`，notes解释冲突。室内unknown不代表现实一定室外；这里的不可行是基于快照证据无法证明满足硬约束，不能凭场馆名称升级标签。用户同时禁止扩候选/自行推断，所以需要核实证据或调整需求。

5个标准无解输出都通过`TravelRoute`和冻结`score_case`；Schema没有`spots`最小长度限制。模型原始JSON仍带非空spots，错误在模型生成阶段已经存在，不能用生产后处理填充来解释本轮现象。当前无解评分使用词语匹配有局限，但这15个SFT最终输出全部非空，失败并非仅因解释没有命中关键词。

## 2. 确认的数据准入冲突

将同一组合法无解输出送入实际使用的`regen_v1_v2_current_protocol.audit()`：

| 正确答案类别 | 冻结评测 | 本次训练审核结果 |
| --- | --- | --- |
| 数量不可行，空spots并解释 | 通过，3/3题 | 全部拒绝：`empty_day_not_independently_proven_infeasible`、`route_structure`、`required_count` |
| 室内证据不足，空spots并解释 | 通过，2/2题 | 全部拒绝：上述错误加`candidate_pool_preference_conflict` |

代码路径：

1. `scripts/regen_v1_v2_current_protocol.py:audit`：任何一天为空，直接追加`empty_day_not_independently_proven_infeasible`；虽错误名写“未独立证明”，实现没有查询任何证明或豁免分支。
2. `scripts/post_train_runtime.py:replay_check`调用`app/planning/nodes.py:_route_risk_flags`，后者把任意空spots记为结构风险（`route_structure`）。
3. 带rubric时又通过`audit_plan`进入`app/evaluation/task_robustness.py:grade`，其`rubric.get('min_count',1)`默认至少1个景点，没有按合法不可行结果区分。
4. 明确室内候选为0时，生产门控还会报候选偏好冲突。这是需要处理的输入条件，不能在不可行答复分支里继续当作“答复本身错误”无限返工。

本轮未把测试原题用于训练，仅将其合法答案作为诊断输入复现审核差异。`required_count`来自这次跨审核函数探针中的默认min_count，其表现同时说明训练rubric和本轮评测rubric语义不同；不据此声称训练原题已有无解样本被这个默认值实际剔除。无条件空行程拒绝则对任意此类输入都成立。

## 3. 实际训练和验证覆盖

| 数据 | 条数 | 含空spots的答案 | 全空不可行答案 | 含unknown候选的输入 |
| --- | ---: | ---: | ---: | ---: |
| v1-current训练 | 156 | 0 | 0 | 0 |
| v2-current训练 | 250 | 0 | 0 | 94 |
| v2-large训练 | 154 | 0 | 0 | 154 |
| 共用验证 | 30 | 0 | 0 | 0 |

v2的250条包含v1的156条，不能把两个版本加起来算独立训练覆盖。验证集0条无解输出、0条unknown候选输入，因此验证loss持续下降不能发现这些能力退步。

进一步窄范围筛查v1/v2训练答案：没有发现“全程至少N个不同景点却不足N个”的明确模式，也没有在`selection_reasons`中命中“unknown候选被称为明确室内/室内展厅”等预设短语。该筛查不等于全量语义审计；目前没有直接证据认定教师训练答案大规模包含本轮相同的矛盾文本。已证实的主问题是覆盖与准入机制，不应把推测写成教师数据污染事实。

## 4. 提示词与生产协议

本轮评测和current v1/v2训练均为同一个生产system及`capture_messages`输入，故本轮无解退步不能简单归因为此前“训练/测试提示词不同”。但当前生产消息自身有两套未明确分支的要求：

- `constraints.contract_text`：恰好数量若与硬约束冲突，应说明不可行。
- `nodes.make_joint_planner_node`：候选不足时“只用已有景点并说明缺口”“宁可少排”。

普通偏好允许降级时少排是合理行为；用户明确要求恰好数量、不接受部分路线时应返回不可行。这两类输入需要显式区分。当前文字存在歧义，是潜在放大因素；用户在5道测试题中已经明确写了应空行程，不能说题目没有交代。

生产门控目前仍视空行程为风险，因此即便模型学会正确输出无解，完整线上流程还需要把“已证明不可行”与“模型漏排/结构错误”分开处理。风险告警本身有用，但不应驱动无意义重复规划，更不能当作通过要求去硬凑路线。本轮Rules+Rework使用独立无解rubric，未受该生产空行程门控限制；其失败不能直接归因于生产门控在测试时拒绝空答案。

## 5. 返工为何没有补救

| 模型 | 直出无解正确 /15 | 返工最终正确 /15 | 返工模式总生成轮数 | 其中正确无解输出 |
| --- | ---: | ---: | ---: | ---: |
| Base | 7 | 8 | 37 | 8 |
| v1-current | 0 | 0 | 60 | 0 |
| v2-current | 0 | 0 | 60 | 0 |
| v2-large | 0 | 0 | 60 | 0 |

三版SFT在这些题上均跑满初稿+3次返工，整个过程都没有生成合法无解答案。不是某轮生成了正确答案又被评分拒绝。

返工只把`infeasible_not_explained; infeasible_unsafe_schedule`等英文代码追加到原始user消息，没有解释代码含义，也没有附上上一轮输出和独立冲突证据。反馈协议需要改进，但三版SFT首轮已经失败，不能把问题全归因于反馈形式。

## 6. 输出语义和审计漏检

v2-current seed42中南京写“按2个候选安排恰好3个不同景点”；三亚、苏州写“仅安排2个……满足恰好3个”。上海、成都选择unknown候选，并声称室内。`explanation_faults()`主要检查游玩分钟数、selection_reasons是否引用选中景点、返工叙述泄露，缺少通用数量命题及属性证据一致性检查。

因此之前“全量审计通过”应准确理解为当时已实现的检查全部通过，不是无解/语义正确性已得到全覆盖。当前这项诊断确认了检查盲区，需要补齐，不能只增加教师请求次数。

## 修复优先级（本次未实施）

1. 先定义有证据的不可行分支：数量鸽巢冲突、可接受候选为空等可独立证明条件；输出保留天数、空spots、具体冲突和可选调整。普通缺候选但用户允许少排，仍按降级处理。
2. 统一训练审核、生产门控、验证与评测对该分支的语义。仅在独立证据成立时允许空行程，不能直接删除所有空行程风险检查或将min_count一律改成0。
3. 加入数量陈述和unknown属性升级的语义校验；保存现有冻结结果，后续评分修订另开版本。
4. 重新审计旧数据后，合成新的成对有解/无解样本：相近输入只改变候选数量、证据或时段；验证集也同时覆盖正确不可行与有解误拒绝。不用当前50题原题答案训练。
5. 用受控补数训练验证是否恢复能力，保留相同基座、超参数与对照；只有在独立新题上兼顾无解正确率和有解成功率，才判断修复有效。

上述是修复建议，不是已发生的改动。本次没有重训、付费调用或改动旧评测分数。
