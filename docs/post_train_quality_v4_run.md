- 48份正见证及183份负控制通过；预检输入+确定性目标最长3129 Token，正式发布仍逐条检查3584上限，禁止截断保留。
- 使用真实生产消息构造边界捕获首轮messages，不将rubric、见证或无解证明塞进模型上下文。输入与冻结开发/独立测试、历史验证集做消息碰撞检查；不使用评测答案或同题改写。真实场馆可以与开发集重叠，不能宣称新训练城市与开发城市独立。

## 受控训练与评测

质量门通过后，分别从原始Qwen2.5-7B-Instruct训练：

1. v4_clean：仅清洗后的历史样本。
2. v4：相同历史样本加合格补数。

两组均LoRA rank16/alpha32/all、LR1e-4、累积16、seed42、cutoff3584、48次优化器更新，最终检查点合并，不按开发集表现挑中间检查点。固定步数控制更新次数，不能控制相同Token和样本曝光；因此另记录实际非padding输入Token、监督Token、样本数，发布前记录理论曝光。对比只是一轮训练种子的开发实验，不能将差值全归因于样本类型。

发布审计内的expected_sample_exposure_at_48_steps按48×16/样本数计算，仅为满累积窗口的名义估计；每个epoch最后不满的累积窗口可能使实际样本数低于该估计。最终解释一律使用训练微批次账本的实际样本与Token合计，不能把该理论值当成实测曝光。

GPU0串行训练与合并，不覆盖v1/v2/v3/MC。两组完成后自动各跑冻结50题×3种子，即300次本地Planner-Only调用；复用v2已有150次同协议记录。报告原始规则、规则+解释、常规/困难、可行/无解、按题配对区间，并单列格式修复诊断。实际Token汇总随报告保存。
