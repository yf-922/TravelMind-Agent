# v2-large 失败诊断（2026-10-25）

本次只读取已有数据、服务器训练配置与日志，并离线重算；未调用教师 API、未启动训练、未修改冻结评分或原始模型输出。

## 已确认事实

- 数据母本为 `release_v2/train.ledger.jsonl` 的历史训练输入，不是 representative50 评测题。原答案被丢弃，扩充候选后由教师重新规划。
- 实际训练 154 条，每条 15 个候选；v2 为 250 条。服务器配置显示从 Qwen2.5-7B-Instruct 基座训练，并非接着 v2 继续训练。完成 3 epochs、30 steps；v2 为 48 steps。
- 训练城市为三亚16、成都47、上海17、南京30、苏州44；评测每城10题。训练天数为1天90、2天41、3天23；评测为1天40、2天5、3天5。
- 训练154条的系统消息全部明确包含 `period只能是morning/afternoon/evening` 等格式契约；冻结评测系统消息不含该契约。评测仍发送 JSON Schema，但生产 Schema 中 period 是带描述的字符串，并非枚举约束。
- 训练目标共450个景点，period全部为正确枚举；扫描目标 start_time/end_time 未发现非法分钟值。训练154条均为非空路线，没有空路线不可行示范。这不等于完成全部语义审计。
- 训练消息与50题评测消息的完全相同交集为0；这只证明没有消息完全重复，不证明语义或资产绝对独立。

## 原始成绩与对称格式诊断

|模型|冻结原始通过|仅格式归一化后通过|
|---|---:|---:|
|Base|15/150|97/150|
|v2|121/150|121/150|
|v2-large|11/150|97/150|

对全部8个模型使用已有 normalize_format 函数：仅将符合请求日期的完整日期时间转换成HH:MM，或由合法开始时间推导无效period标签；不改景点、顺序、时间数值或规则。诊断结果单独保存为 `data/post_train/representative_eval50_v1/all_versions_v2/format_diagnostic_20261025.json`。诊断分不是新的正式成绩。

v2-large 有139条发生表示归一化，其中86条因此通过。典型原始失败：两个景点时间合法，但 period 为 `09:30 - 10:30`、`11:00 - 12:00`，触发 route_structure。

归一化后仍有21条发生 invalid clock（包括分钟为60等非法时间）；其余失败还包括开放窗口12条、通勤9条、最低停留5条等，各类可能重叠。不能称为纯评分问题，原始格式在生产规则中也有影响。

## 因果判断边界

已确认低分主要受输出契约不一致及格式泛化失败影响。尚未通过控制实验确认提示词差异能解释多少，也不能断言候选池扩容导致能力下降。相比v2，同时改变了数据量、教师答案、输入协议、城市分布和训练步数，当前不是单变量实验。

训练数据格式本身正确；较少样本/更新步数可能使模型更依赖训练时的明确约束，但这是待验证假说。所有候选池固定15个、无空路线不可行示范，也造成覆盖缺口，不能单独解释整体低分。

此外，历史导出脚本将未逐条读过的记录也标为 semantic_pass。实际语义阅读样本仅37条，不能宣称154条均通过完整语义审计。

## 建议验证顺序

1. 建立新版本评测协议，对Base/v2/large同时加入与训练一致的格式契约，在同50题×3 seeds比较，保留旧协议成绩。禁止只给large补提示词。
2. 分别统计格式通过、非法时间、规则通过和规则+解释通过；审查训练集、合并权重及实际加载身份绑定，不能只看总通过率。
3. 在固定协议下若large仍落后，先用原训练输入做小型格式/时间诊断，再比较相同154条与不同步数，区分拟合不足和迁移问题。
4. 依据剩余错误少量补充合法时钟进位、开放窗口+道路衔接、多日去重及明确不可行示范；用新的训练题，避免复制开发集答案。不立即大规模合成或进入DPO。
