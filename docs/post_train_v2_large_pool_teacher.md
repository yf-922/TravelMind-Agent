# v2 扩池、教师从零规划的 SFT 实验

本方案取代此前“扩测试集”和“保留历史答案扩训练输入”的提议。用户已确认：教师不参考旧答案，只对新输入重新规划。

## 目的与边界

检验更充足的同城候选与重新生成的合格答案，能否提高小模型多日去重、选点与联合约束能力。保留 v2 的用户需求分布，输入采用当前生产协议。因此实验同时改变候选规模、教师答案和提示协议，不能把改善或退步全部归因于候选数量。

冻结既有五城市 50 题开发集和独立测试集。训练构造不读取评测答案、可行性见证或改写评测原题；不改变生产代码和冻结评分器，不启动 DPO。

## 阶段一：构造与审计输入

从 v2 的 250 条账本仅提取 id 和输入字段，通过白名单重建初始状态。清除旧路线、审核意见、历史对话、改写、选择理由及上版总结。每个状态保留原候选并补足至 15 个真实同城候选，不通过随机替换删除必去点。复用独立训练检索资产；上海、三亚补做训练检索。新增检索与道路记录均落盘。

开放时间保留来源与原文，采用保守交集快照；不把快照宣传为实时运营保证。室内属性使用三值协议，不把名称或分类推断当成可靠 true。既有有官方证据且明确只参观馆内展厅的状态可保留该范围标签。室内强要求而没有可靠室内候选、或步行要求却没有真实步行道路证据的状态先隔离，不伪造可行性或用驾车数据代替。

预期效果：每条待调用输入至少 15 个候选，无旧答案信息；候选与道路可追溯。输出候选数量、隔离原因、城市/天气/天数分布及输入 Token 长度，披露相对 v2 的分布变化。

## 阶段二：10 例教师试生成

选五城市各两例，覆盖多日、天气、必去/排除、严格时间边界。教师模型 gpt-6.1-sol，直接捕获实际 Joint Planner messages，不添加旧答案或人工选点建议。仅允许本次新草稿失败后的一次规则反馈返工。无 LLM Reviewer。

先跑 10 例，最多 20 次付费调用。当前历史累计 616 次；全量合成拟总上限 300 次（包含试跑），全局硬上限 1000，当前余量允许最多 916 次并保留 84 次。并发 4、超时 90 秒、SDK 不隐式重试。调用、原始输出、用量和失败均记账。无法确认单价时只报告 Token，不猜费用。

验收分别检查：原始 JSON Schema、候选越界、天结构、全程去重、用户数量/时段/最短游玩、开放与最后入场、真实道路通勤、雨天/高温协议、引用合法、解释中的人数/景点数量与时长等可验证事实。教师输出不做模板替换，失败则返工或隔离。规则通过不等于所有语义都已证明；保留原文供逐条试跑审阅。

用本地 Qwen tokenizer 检查真实消息加答案的长度，3584 以上不直接导入训练；先诊断，禁止静默截断。若大量超长，需要另行确定是否调整上下文与显存配置，不能偷偷删候选破坏实验。

## 阶段三：全量合成与发布

试跑审阅后再扩大，首次生成优先于返工，整体至多 50 次返工。目标为可证明合格的数据，不保证机械凑足 250 条。断点续跑不重复已完成样本，输入与代码绑定，发生改动需新版本。导出直接取首轮捕获 messages，训练答案取通过审计的新教师答案，导出后验证数量与消息一致。发布清单记录来源、hash、Token 分布、通过率、返工率、隔离率和主题分布。

## 阶段四：SFT 与效果比较

先做长度与 4090 显存冒烟，通过后在 /home/jiale、GPU0 训练。以与 v2 相同的基座和主要 LoRA 配置为起点，同时报告实际训练样本暴露、非 padding 输入及监督 Token，不能仅用同 48 步宣称训练量相同。训练与评测时间依据试跑吞吐估算，不预先保证。

冻结五城市 50 题，每题三个生成种子对照 v2 与新模型，使用配对胜/负/平和正常/困难分层结果。核心指标为硬约束首轮通过率、规则与解释联合通过率、重复/越界/错误拒绝率、逐条选点理由时长一致率，以及正常 40 题上的成功率。补充记录高温/雨天/数量/多日子类、延迟与 Token。三次生成衡量推理波动，不代表三次独立训练；只有一个训练种子时明确限制。

本实验验证通过后再决定是否 DPO。最终产品结论仍需 Base、最佳 SFT、SFT+DPO、线上 API 四组按同一协议比较；API 基线单独预算，不混入这次训练合成调用。
