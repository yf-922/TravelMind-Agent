主评测：50 场景 × 3 共同 seed，45 个可行场景的 135 次生成用于下表；另 15 次无解生成单列。首轮与最多 3 次本地规则反馈返工共用轨迹。无外部 Reviewer 调用。结果来自历史落盘报告与 Token 账本重聚合，本次仅更新文档。

| 版本 | 首轮可行集通过率 | 规则闭环通过率 |
| :--- | ---: | ---: |
| Base | 49.6% | 50.4% |
| v2-SFT | 64.4% | 70.4% |
| v2-DPO | 61.5% | 69.6% |
| A-SFT | 39.3% | 46.7% |
| A-DPO | 43.0% | 48.9% |

## 数据迭代与归因

- 旧数据时间边界标签存在错误，模型过度偏好整点 / 半点；清洗后保留 343 条历史数据，加入 90 个新上下文，其中包含 20 条规则反馈后的修正样本，总计 433 条 SFT 与 433 对 DPO。
- 最终 SFT 从 Base 重训，DPO 从合并后的最终 SFT 父模型训练。阶段间同时改变数据清洗与分布，因此不是针对单一数据因素的独立因果消融。
- B-DPO 首轮时间窗违约 34/135，C-DPO 12/135；B-SFT / B-DPO 返工挽回率 32.6% / 17.9%，C-SFT / C-DPO 为 50.0% / 35.3%。最终 DPO 改善首轮，但最终 SFT 的失败挽回率仍更高。

## Token 账本

仅统计 135 次可行任务的 Planner 输入 + 输出，包含首轮与最多 3 次额外返工；不包含预热和 15 次无解任务。

| 模型 | 首轮 Token | 返工 Token | 累计 Token | 额外调用数 |
| :--- | ---: | ---: | ---: | ---: |
| Base | 428,337 | 689,905 | 1,118,242 | 202 |
| C-SFT | 423,846 | 174,483 | 598,329 | 52 |
| C-DPO | 424,718 | 136,179 | 560,897 | 41 |

C-DPO 较 Base 节省 49.84%，较 C-SFT 节省 6.26%。后二者终态均为 124/135；成本差主要来自更少返工，未检验统计显著性。不能与全 150 次的总 Token 或单次输出 Token 混用。

## 地点核验与外部对照边界

- 首轮带池 Base 为 2/345 个池外实体（0.58%），最终 DPO 为 0/328；按出现次数计数，不是按去重地点计数。
- 无池预注册核验报告记录 346 个实体：城市内可核验 215、类别错误 55、近名不匹配 / 搜不到 75、待核验 1。尚待人工复核，不将其写成最终“97.6% 幻觉率”。池外率与不可核验率是不同指标，不能直接串成因果链。
- GPT-6.1-sol JSON-mode 同冻结任务首轮可行通过率 91.1%；它是 Planner 对照，不是人工标注的理论上界。外部 API 延迟不与本地 vLLM 混比。
- 最终两模型无解合规拒答均 0/15。关键词识别不能替代空路线与冲突解释的合规判定。
- 测试集指纹去重仅支持未发现精确重合；不能证明无语义重合。冻结集已用于失败诊断，后续结论需要新盲测。
