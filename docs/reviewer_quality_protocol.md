# Reviewer 专项对照评测

30 条控制草案：偏好 8、节奏 8、天气 7、通勤 7。6 条正常对照、24 条预先注入缺陷，标注为作者草稿；不表示自然请求错误分布。

四组共用同一草案：仅 Planner 草案、仅规则、当前风险门控审核、强制 Reviewer 审核。真实调用生产联合 Planner、Reviewer 和 Time Check；外围查询固定，道路使用已保存高德响应，开放时间控制为 09:00–18:00。不跑实时搜索和可选贴士。

偏好检查明确排除景点，节奏检查数量和至少 60 分钟停留，天气检查雨天室内，通勤检查相邻安排间隔是否大于回放道路耗时。最终路线字段评分；说明文字不算修复。报告另列批准状态、正常对照退化、失败和未执行请求。

偏好排除是可确定的约束，不代表所有兴趣软偏好；60 分钟是用例显式要求，不是通用游览规则。没有独立 Judge 或人工确认，不能将本次数字包装为线上用户质量。

```powershell

python scripts/summarize_reviewer_quality.py --report data/eval/reviewer_quality_real.json --out data/eval/reviewer_quality_analysis.json

```

模型失败不重试，失败行保留；恢复命令只执行未记录行。不结算的调用禁止恢复。实际 Token 来自 provider usage，成本保持 unpriced。代码或资产变化禁止静默复用。

另一份原始实验 `data/eval/audit_value_real.json` 保留了 30 个自然请求与 10 个无解请求的部分结果。其中三亚室内/雨天请求因候选全户外，不能作为可满足请求；补跑报告为 `audit_value_supplemental.json`，失败不删除。原实验没有完成全部无解组，不可报告 10/10。
