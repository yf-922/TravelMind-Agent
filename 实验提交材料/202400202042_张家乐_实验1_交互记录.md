# 实验1交互记录（整理版）

说明：以下记录根据项目开发过程整理；带“模拟”标记的内容用于补全需求讨论，不作为系统运行日志。

| 轮次 | 输入/问题 | 关键结论 |
|---|---|---|
| 1 | 我想做旅游助手，是否只用一个 Agent？ | 不建议。先拆为意图、检索、规划、审核，保证职责不重叠。 |
| 2 | 候选池没有用户想去的景点会怎样？ | 先通过高德重新检索并核验，再合并候选池后重规划。 |
| 3 | 用户偏好存在哪里？ | 用户画像与行程历史存 SQLite；不同 Agent 的工作记忆独立存放。 |
| 4 | 门票是否提前放进 RAG？ | 不放。票价属于易变信息，应在展示时实时查询；失败时标注未计价。 |
| 5（模拟） | 验收怎样写才算可检查？ | 用“输入—期望输出—判断条件”表达，例如所有行程景点必须属于候选池。 |

需求调整结果：项目从“自动生成旅游攻略”收敛为“基于真实 POI 和集中式调度的可验证旅行规划系统”。
