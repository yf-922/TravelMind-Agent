# 实验1交付物：TravelMind 需求/立项文档

## 1. 项目名称

TravelMind——基于多智能体协作的旅行规划助手。

## 2. 问题、用户与场景

目标用户为自由行游客，尤其是需要在有限时间内综合考虑景点、餐饮、交通、天气、预算与个人偏好的人群。传统搜索需要在地图、攻略、购票和餐饮平台之间反复切换；单一大模型直接生成行程又可能编造景点、遗漏约束或给出不可执行路线。

典型场景：用户输入“北京两日文化游，节奏慢，想吃本地小吃”，系统识别目的地和日期，检索真实 POI，生成行程并复核，再展示交通、预算与景点提示。

## 3. 核心功能

1. 意图识别：抽取目的地、日期、景点/餐饮/节奏偏好；缺字段时提示补充。
2. 真实数据检索：调用高德 POI、天气和路线工具，建立候选池。
3. 行程编排与审核：Planner 生成草案，Reviewer 检查候选池一致性和可执行性，必要时返工。
4. 旅行增强：餐饮、门票、交通、酒店推荐与预算展示；动态数据失败时明确降级。
5. 记忆与历史：保存用户画像和行程历史，区分用户事实、任务状态与各 Agent 私有记忆。

## 4. 数据来源

| 类型 | 来源 | 用途 |
|---|---|---|
| 用户输入 | Web 前端自然语言 | 目的地、日期、偏好、预算约束 |
| 地点/路线/天气 | 高德开放平台 API | POI 候选池、交通、天气 |
| 旅行知识 | 本地旅行知识文档 + RAG | 旅游常识与安全提示 |
| 持久化数据 | SQLite | 用户画像、历史行程、Agent 记忆 |

## 5. 多智能体分工设想

| 智能体 | 职责 | 输入 | 输出 | 独立原因 |
|---|---|---|---|---|
| IntentAgent | 抽取旅行约束 | 用户请求 | 目的地、日期、偏好 | 不负责检索，避免上下文职责混杂 |
| POIResearchAgent | 调用地点工具、形成候选池 | 目的地、查询 | 真实候选 POI | 工具权限独立，防止 Planner 直接编造地点 |
| PlannerAgent | 基于候选池排日程 | 约束、候选池 | 行程草案 | 专注时间与地理顺序优化 |
| ReviewerAgent | 审核、提出返工意见 | 草案、候选池 | 通过/返工意见 | 与生成职责分离，避免自我确认偏差 |

## 6. 可检验验收标准

1. 输入合法目的地和日期后，系统返回非空行程，且行程景点均来自已检索候选池。
2. 每次主链路均出现 Intent、POI Research、Planner、Reviewer 的调度记录。
3. 每个 Agent 有独立系统提示和私有记忆；测试中一个 Agent 的记忆不出现在另一 Agent 中。
4. Reviewer 未通过时，Supervisor 最多触发一次 Planner 返工，不进入无限循环。
5. Worker 超时/异常时返回结构化失败信息或降级提示，不整体崩溃。

## 7. 实际仓库证据

- 调度核心：`app/multi_agent_core/supervisor.py`
- Agent 实例与私有记忆：`app/multi_agent_core/agents.py`、`memory.py`
- 实际 Web 规划链路：`app/planning/graph.py`、`app/planning/nodes.py`
- 运行方式：`./.venv/Scripts/python.exe run.py`，浏览器访问 `http://localhost:8765`
