# 实验1：需求分析与立项实验报告

姓名：张家乐　学号：202400202042　项目：TravelMind 多智能体旅行规划助手

## 一、实验目的

1. 掌握 AI 驱动项目的需求分析与立项方法。
2. 能够针对旅行规划场景提出合理的多智能体分工设想。
3. 形成可执行、可检验的需求文档，为后续设计、实现和测试提供依据。

## 二、实验内容

本实验围绕“旅行/活动规划”主题确定项目范围。系统面向自由行用户，解决旅行信息分散、约束难综合、模型可能编造地点的问题。项目以 Python、FastAPI、LangGraph、SQLite 和高德 API 为基础，设计 IntentAgent、POIResearchAgent、PlannerAgent、ReviewerAgent 四类角色，并给出数据来源、功能边界与验收标准。

与单 Agent 相比，多 Agent 的必要性在于：意图抽取、真实检索、日程生成和质量审核的目标不同。将它们拆分后，可限定 POIResearchAgent 的工具权限；Planner 只能使用候选池；Reviewer 可以独立发现候选池外地点或不合理草案，从而更容易定位与迭代问题。

## 三、实验步骤

1. 选择旅行规划场景，列出用户输入、外部数据、输出行程和失败风险。
2. 将需求收敛为意图识别、真实 POI、规划审核、交通预算、记忆历史五项核心功能，避免做成无边界的“通用助手”。
3. 将功能按职责拆分为四类 Agent，明确每个 Agent 的输入、输出与不负责事项。
4. 将“效果好”改写为可验证标准，例如“景点来自候选池”“审核不通过最多返工一次”“异常返回结构化错误”。
5. 将需求写入仓库文档，并在后续实现中以测试验证验收标准。

## 四、心得体会

需求分析阶段最重要的是限制边界。旅行规划看起来涉及所有旅游信息，但本项目只承诺使用已接入的真实工具和候选池数据；实时数据拿不到时明确提示，而不是由模型猜测。多 Agent 并非为了增加角色数量，而是让每个角色有可独立测试的目标和边界，为后续记忆隔离、工具权限和失败重试打下基础。
