# 实验2：概要设计与详细设计实验报告

姓名：张家乐　学号：202400202042

## 一、实验目的

1. 掌握多智能体系统的概要与详细设计方法。
2. 能够用架构图、流程图表达分工和交互。
3. 形成可指导后续编码实现的设计文档。

## 二、实验内容

本实验采用集中式 Supervisor 模式。Supervisor 控制路由，Worker Agent 不自行调度其他 Worker；主链路为 Intent→POI Research→Planner→Reviewer。Reviewer 通过后输出，未通过时最多将任务返给 Planner 一次。外部 POI/RAG 工具仅授权给检索角色，避免工具权限混用。

详细设计包含 Agent 设计卡、带 `task_id/session_id/task_type/from/to/content/status/attempt` 的消息模型，以及独立内存方案。系统采用“消息共享而非消息列表共享”：下游只获得必要结构化字段，私有 memory 保留在 Agent 实例或 SQLite 存储中。

## 三、实验步骤

1. 以用户请求进入系统、最终行程离开系统为主线绘制架构图。
2. 识别职责冲突：将“找地点”和“排日程”分开，Reviewer 不直接修改行程。
3. 根据可追踪、可重试需求补充 `trace_id`、`attempt` 和 `status` 字段。
4. 按“谁产生、谁需要、谁不应看到”原则划分记忆。
5. 设计失败路径：Worker 抛异常后由 Supervisor 有限重试，仍失败时返回结构化错误。

## 四、心得体会

设计阶段使我认识到，图中有多个方框并不代表真正的多智能体。只有角色目标、系统提示、工具权限和记忆都独立，且调度关系可解释，才满足多 Agent 红线。消息结构应尽早固定，否则实现后期很容易出现字段丢失、下游依赖不清和异常无法定位的问题。
