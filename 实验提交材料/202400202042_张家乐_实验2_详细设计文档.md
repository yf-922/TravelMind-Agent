# 实验2详细设计文档：TravelMind 多智能体系统

## 1. 设计目标与范围

本设计采用集中式 Supervisor 编排。目标是在旅行规划中将“理解需求、核验地点、生成行程、审查行程”分配给不同 Agent，避免单一模型同时承担全部职责导致的地点编造、角色混乱和上下文污染。

本实验的范围是多智能体核心设计，不把实时票价、完整网页交互或模型训练作为本实验承诺。主链路为固定顺序，Reviewer 驳回和 Worker 失败时由 Supervisor 条件路由。

## 2. 总体架构与控制流

架构图文件：[实验2架构图.svg](202400202042_张家乐_实验2_架构图.svg)。

1. 用户需求交给 Supervisor，Supervisor 创建 `task_id`、`session_id` 与任务日志。
2. Supervisor 向 IntentAgent 分发 `intent_extract`，得到目的地和旅行约束。
3. Supervisor 向 POIResearchAgent 分发 `poi_research`。该 Agent 可调用 `poi_search`，返回结构化候选池。
4. Supervisor 将意图和候选池交给 PlannerAgent；Planner 只能从候选池选择景点。
5. Supervisor 向 ReviewerAgent 发 `itinerary_review`。审核通过则结束；不通过则最多一次向 Planner 发送 `itinerary_revise`，然后复审。
6. 任一 Worker 异常时，Supervisor 最多重试两次；耗尽重试后返回含 `failed_agent`、`error_code` 的结构化失败结果。

## 3. Agent 详细设计卡

### 3.1 Supervisor

- 目标：执行集中式任务分发、记录调度轨迹、处理条件路由和失败重试。
- 能做：创建任务消息；按状态选择下一 Agent；限制返工和重试次数；返回结果或结构化失败。
- 不做：不生成旅游内容；不调用 POI 工具；不读取 Worker 私有记忆。
- 记忆：仅 `dispatch_log`，范围是单次任务状态。
- 工具：无业务工具。

### 3.2 IntentAgent

- 目标：从用户请求中提取目的地、日期、人数、预算、节奏和饮食偏好。
- 能做：输出结构化意图和缺失字段提示。
- 不做：不搜索 POI，不生成具体景点或路线。
- 输入/输出：输入 `user_request`、`destination_hint`；输出 `destination`、`constraints`。
- 记忆：私有意图抽取记录，不能被 Planner 或 Reviewer 直接读取。

### 3.3 POIResearchAgent

- 目标：使用 POI 工具核验候选景点，避免 Planner 凭空生成地点。
- 能做：调用 `poi_search`；返回候选名称、地址和工具来源。
- 不做：不排时间表，不决定预算，不审核行程。
- 输入/输出：输入 `destination`、`place_query`；输出 `candidates`。
- 记忆：私有检索任务和工具返回记录。
- 工具权限：仅本 Agent 拥有 `poi_search`。

### 3.4 PlannerAgent

- 目标：把意图和候选池转为有顺序的行程草案。
- 能做：根据用户约束选择候选池景点；收到返工意见后修订一次。
- 不做：不直接调用 POI 工具；不使用候选池外景点；不对自己的方案作最终审核。
- 输入/输出：输入 `intent`、`candidates`、可选 `review_instruction`；输出 `itinerary`。
- 记忆：私有草案、修订指令与修订记录。

### 3.5 ReviewerAgent

- 目标：发现行程中候选池外地点、空行程和完整性问题。
- 能做：输出 `approved`、`issues`、`revision_instruction`。
- 不做：不直接改写行程；不调用 POI 工具；不控制下一步调度。
- 输入/输出：输入 `itinerary`、`candidates`；输出审核结论。
- 记忆：私有审核记录。

## 4. 消息结构

```json
{
  "task_id": "trip-uuid",
  "session_id": "session-uuid",
  "task_type": "itinerary_plan",
  "from": "supervisor",
  "to": "planner_agent",
  "content": {"intent": {}, "candidates": []},
  "status": "running",
  "attempt": 0,
  "trace_id": "trace-uuid",
  "created_at": "2026-07-28T00:00:00Z",
  "error_code": null
}
```

| 字段 | 含义 |
| --- | --- |
| `task_id` / `trace_id` | 标识一次任务和完整链路，便于关联日志。 |
| `session_id` | 用户会话范围，用于记忆隔离。 |
| `task_type` | 任务语义：`intent_extract`、`poi_research`、`itinerary_plan`、`itinerary_review`、`itinerary_revise`。 |
| `from` / `to` | 消息发送 Agent 与接收 Agent。 |
| `content` | 仅携带接收方完成任务所需的结构化数据。 |
| `status` | `running`、`done`、`failed`、`retrying`。 |
| `attempt` / `error_code` | 记录重试次数和最终错误类型。 |

## 5. 记忆隔离方案

| 记忆项 | 归属 | 是否共享 | 隔离规则 |
| --- | --- | --- | --- |
| 用户原始请求 | Supervisor 任务消息 | 按需只读传递 | 不作为全局对话历史灌给 Worker。 |
| 意图抽取记录 | IntentAgent | 私有 | 键为 `session_id + intent_agent`。 |
| POI 检索记录 | POIResearchAgent | 私有 | 只向 Planner 输出结构化候选池，不输出私有 Prompt/记忆。 |
| 行程草案与返工记录 | PlannerAgent | 私有 | Reviewer 只收到当前草案和候选池。 |
| 审核记录 | ReviewerAgent | 私有 | 仅以 `revision_instruction` 反馈可执行修订意见。 |
| 调度轨迹 | Supervisor | 任务内共享日志 | 不包含 Worker 私有记忆。 |

SQLite 存储以 `(session_id, agent_name, position)` 为主键，因此不同用户会话与不同 Agent 的记录不能互相覆盖或读取。

## 6. 实现映射与验收

| 设计项 | 实现文件 | 验收方式 |
| --- | --- | --- |
| 集中式调度、返工、重试 | `app/multi_agent_core/supervisor.py` | `test_multi_agent_core.py` 的调度、返工、失败重试测试。 |
| 独立 Prompt 与私有记忆 | `app/multi_agent_core/agents.py` | 私有 memory 不同对象、不同内容；日志打印各 Agent memory。 |
| SQLite 记忆隔离 | `app/multi_agent_core/memory.py` | `test_sqlite_memory_is_isolated_by_session_and_agent`。 |
| 工具权限 | `app/multi_agent_core/tools.py` | 未授权 Agent 调用 `poi_search` 抛出 `ToolPermissionError`。 |
| 结构化消息 | `app/multi_agent_core/messages.py` | `AgentMessage` 的字段与运行 `dispatch_log`。 |
