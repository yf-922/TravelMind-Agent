# 实验4交付物：测试集、测试代码与协作观察报告

## 1. 测试资产

| 类型 | 文件/产物 | 说明 |
|---|---|---|
| Agent 单元测试 | `tests/test_agent_unit_contracts.py` | Intent、POI、Planner 三类 Agent |
| 多 Agent 集成测试 | `tests/test_multi_agent_core.py` | 调度、返工、重试、工具权限、记忆隔离 |
| 端到端测试 | `tests/test_e2e_evaluation.py` | 10 条 Golden Set 请求 |
| 评估脚本 | `scripts/generate_eval_report.py` | 生成离线可复现 JSON 报告 |
| LLM 评审 | `scripts/run_llm_judge.py` | 结构化 LLM-as-Judge 评分 |
| 评估报告 | `evaluation/latest_report.json`、`llm_judge_report.json` | 成功率、延迟、失败分类 |

## 2. 三组代表性测试用例

| 用例 | 输入 | 期望协作 | 观察结果 |
|---|---|---|---|
| 正常 | 北京文化一日游 | Intent→POI→Planner→Reviewer | 四 Agent 被调度，行程非空，审核通过 |
| 返工 | Planner 首版故意返回空行程 | Reviewer→Planner revise→Reviewer | 发生一次返工后通过，不死循环 |
| 异常 | IntentAgent 模拟 TimeoutError | Supervisor 重试→结构化失败 | 重试两次后返回 failed_agent 和 error_code |

## 3. 实测结果

- `pytest -q`：68 passed（本次项目快照）。
- 离线端到端 Golden Set：10/10 通过，平均延迟约 0.11 ms（Fixture 环境）。
- LLM-as-Judge：10/10 得到结构化评分，Judge 通过率 80%，平均 Judge 延迟约 3.00 秒。
- 失败分类：`constraint_miss` 2 条，主要是“慢节奏/餐饮偏好”只达到基本满足。

## 4. 优化前后对比

| 观察问题 | 优化 | 对比结论 |
|---|---|---|
| 规划草案可能不合格 | 加入 Reviewer 返工路由 | 不合格草案不会直接输出，返工次数受限 |
| 工具失败可能中断流程 | Supervisor 重试和结构化失败结果 | 单个 Worker 故障可被上游捕获 |
| 偏好满足难量化 | 引入固定 Prompt、temperature=0 的 LLM Judge | 可记录分项分数和失败类型 |
