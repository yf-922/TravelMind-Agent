# 实验4：测试与评估实验报告

姓名：张家乐　学号：202400202042

## 一、实验目的

1. 掌握多智能体系统测试用例设计与评测记录方法。
2. 能够通过定性和定量观察定位协作问题。
3. 形成答辩前的质量与改进证据。

## 二、实验内容

本实验采用单元、集成、端到端三层测试。单元测试验证各 Agent 的输入输出契约、私有记忆和候选池约束；集成测试验证 Supervisor 调度、条件返工、工具权限和失败重试；端到端测试使用 10 条固定 Golden Set 请求验证完整协作链路。

为避免只凭主观感受评价，项目额外实现 LLM-as-Judge。Judge 使用固定 `travelmind-judge-v1` Prompt、temperature=0 和 Pydantic 结构化评分，按候选池一致性、需求满足、行程完整性、Reviewer 一致性和表达清晰度评分，并保存报告以供复现比较。

## 三、实验步骤

1. 设计正常、返工、超时异常三类复合任务，明确每个 Agent 的预期行为。
2. 编写 pytest：验证调度顺序、行程非空、候选池一致性、私有 memory 隔离和重试次数。
3. 运行 `pytest -q`，记录通过数；运行 `generate_eval_report.py` 生成离线端到端报告。
4. 运行 `run_llm_judge.py`，记录 Judge 版本、通过率、延迟和失败类别。
5. 针对 `constraint_miss` 分析原因，形成“显式传递偏好、增加可验证约束字段、收集真实失败请求”的优化清单。

## 四、心得体会

测试多智能体系统不能只检查“最后能否回答”。更重要的是检查谁被调用、信息是否传到下游、不同角色是否相互污染、失败是否可控。固定用例和结构化评估报告让每次改动后都可以比较，而 LLM Judge 只能作为辅助评审，仍需要结合人工抽查和真实工具环境测试。
